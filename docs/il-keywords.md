# IL 关键词速查手册（给人类看的）

> 这份文档给**人**用：开发者、审计者、想读懂档案的非程序员。
> 完整的语言规则见 `il-spec.md`；这里是关键词的速查与详解，按"看到它就该知道这段在讲什么"来组织。

---

## 0. 一页总览

一份 IL 档案从头到尾只有这几层结构：

```
┌─ 档案头：这段产物是谁、属于哪类、要锁多像、用什么做
│    INTENT  KIND  FIDELITY  TARGET
│
├─ CONTRACT   R1 R2 R3 …        "必须这样"（核心契约）
├─ ANCHORS    in/out  style …   "照着这些例子和风格做"
├─ SNIPPET <标签>                 "这一段原文必须逐字出现"
├─ ACCEPT     A1 A2 A3 …        "怎么算对"（验收用例）
├─ DECISIONS  D1 D2 D3 …        "决定过什么、否决过什么"
├─ OPEN       ?1 ?2 …           "还没定的点，先按默认做"
└─ META                          "档案元信息（系统维护，人不用写）"
```

关键词一共就三类：**头部字段**（4）、**段落名**（7）、**行内标签**（约 6）。下面逐个讲。

---

## 1. 档案头：四个字段

出现在文件最顶部，每个字段一行，`字段名 空格 值`。

| 关键词 | 含义（大白话） | 例子 |
|---|---|---|
| `INTENT` | 这个产物叫什么、哪个版本 | `INTENT 计算器@1.5` |
| `KIND` | 产物是哪种东西 | `KIND program`（程序）/ `document` / `service` |
| `FIDELITY` | 复现时要"像到什么程度" | `FIDELITY behavior` / `structure` / `artifact` |
| `TARGET` | 用什么技术做、什么形态 | `TARGET python single-file` |

### FIDELITY 的三个值（最关键的理解点）

| 值 | 要求的"一致" | 允许的自由 |
|---|---|---|
| `behavior` | 行为一样（同输入同输出） | 代码怎么写随便 |
| `structure` | 行为 + 结构/接口/布局一样 | 命名等细节自由 |
| `artifact` | 连长相细节都一样 | 几乎没自由，靠 SNIPPET 贴原文 |

> 三个值是"锁得多紧"，不是"质量好坏"。锁越紧，档案越要写细、成本越高。
> 想要"长得也一样"的部分，必须靠 `SNIPPET` 原文锁定，光写 FIDELITY 不够。

## 2. 七个段落名

段落名独占一行、顶格、大写。段名后面跟着属于它的一行行内容。

### `CONTRACT` —— 契约（最核心）

写"**必须这样**"的约束。每条一个编号 `R`。

```
CONTRACT
  R1: 每次读一行，格式是"整数 运算符 整数"
  R3: 含字母、多运算符或空格 → 打印"非法输入"继续，不退出
```

- 规则：**只写已经确定的事实**。还有疑问的放 `OPEN`，别硬写。
- 可以写否定："不做 X"、"不支持 Y"。

### `ANCHORS` —— 锚点

给 AI 的"例子和口味"，约束力比描述强。

```
ANCHORS
  in: '5+3'   out: '8'
  style: 用中文提示，无第三方库
```

- `in:`/`out:`：一组输入输出例子。
- `style:`：一句话的风格/命名/结构偏好。

### `SNIPPET` —— 黄金代码（点名锁定）

**当你要某段代码"原样出现"时**，贴进来。段名后可带一个标签，方便引用。

```
SNIPPET main_loop
  while True:
      expr = input('> ').strip()
```

- 复现时这段会被要求**逐字**放入产物，不许改写、重排。
- 用来锁 GUI 布局数组、核心算法这类"必须一字不差"的东西。

### `ACCEPT` —— 验收用例

写"**怎么算对**"，每条一个编号 `A`，必须是能判定对错的说法。

```
ACCEPT
  A1: 输入 "5+3" 输出 "8"
  A4: 输入 "10/2" 提示"非法输入"
```

- 这是整个语言里"对"的最终裁判：产物被拿这些用例一个个测。
- 复现的 AI 交付前要自检这些全过。

### `DECISIONS` —— 决策日志

记录"决定过什么、**否决过什么**"，防止复现的 AI 把砍掉的选项捡回来。

```
DECISIONS
  D1: 只支持 + - ×     reject: 除法     due: 用户没要求
```

- 每条含三个部分：决定了什么 / `reject:` 被否决的**备选方案** / `due:` 为什么。
- ⚠️ 重要：`reject:` 只写"这次讨论中提出过、被否定的**备选**"。**不要写"改动前的旧状态"**——旧状态不是备选，写进去会让后人误读成"这东西被禁了"。

### `OPEN` —— 开放项

写"**还没定**的点"，必须带一个默认值。

```
OPEN
  ?1: 结果要不要带 "=" 前缀     default: 不带
```

- 规则：没定 ≠ 不说。复现的 AI 遇到它按 `default:` 做，不许自由发挥。
- 以后聊定了，可以把这项移进 `CONTRACT`。

### `META` —— 元信息（不用人写）

档案的"档案信息"：用了哪个规范版本、建了多少次、作废过哪些编号。

```
META
  spec: v1.0
  commits: 7
  deprecated: []
```

- **由系统自动维护**，人类看可以，不用写；也明确禁止 AI 改。

## 3. 条目编号前缀

段内每一条用编号开头，表示它是段里的第几条。

| 前缀 | 出现在 | 例子 | 含义 |
|---|---|---|---|
| `R` | `CONTRACT` | `R1` | 契约第 1 条 |
| `A` | `ACCEPT` | `A1` | 验收第 1 条 |
| `D` | `DECISIONS` | `D1` | 决策第 1 条 |
| `?` | `OPEN` | `?1` | 开放第 1 项 |

**编号的规矩**：
- 只增不减：新内容用下一个新号。
- 改某条 → 改正文、**保留原编号**。
- 删某条 → 直接删行，编号作废不再复用。
- 这样历史可追溯：`R1` 从出生到现在的每一次改动，都能在档案历史里查到。

---

## 4. 行内标签

出现在一行内容里的"小标签"，后面跟冒号。

| 标签 | 用在 | 意思 |
|---|---|---|
| `reject:` | `DECISIONS` | 否决掉的选项 |
| `due:` | `DECISIONS` | 这么决定/否决的原因 |
| `default:` | `OPEN` | 开放项暂时按什么做 |
| `in:` / `out:` | `ANCHORS` | 一组输入 / 期望输出 |
| `style:` | `ANCHORS` | 风格口味的一句话 |

---

## 5. 注释与符号

| 符号 | 意思 | 例子 |
|---|---|---|
| `#`（行首） | 注释，给人看的说明 | `# 这条为什么这么定` |
| `->` | "输出/变成" | `R1: add(a,b) -> a+b` |
| 两空格缩进 | 表明这行属于上面那个段 | 见本文所有示例 |
| "不做/不支持" | 显式否定 | `R6: 不做运算符优先级` |

## 6. 一段"加了标注"的完整示例

下面用 `←` 标出每个关键词属于哪一类，方便一眼对照：

```
INTENT 命令行计算器@1.0        ← 头部字段：产物名
KIND program                  ← 头部字段：类型
FIDELITY structure            ← 头部字段：锁多像
TARGET python single-file     ← 头部字段：技术栈

CONTRACT                      ← 段落：契约
  R1: 每次读一行算式           ← 编号条目
  R2: 含空格或字母 → 报"非法输入"继续   ← 用到 -> 和否定语义

ANCHORS                       ← 段落：锚点
  in: '5+3'   out: '8'        ← 行内标签
  style: 中文提示             ← 行内标签

SNIPPET loop                  ← 段落：点名锁定（loop 是标签）
  while True:                 ← 原文，逐字保留
      expr = input('> ').strip()

ACCEPT                        ← 段落：验收
  A1: 输入 "5+3" 输出 "8"     ← 编号条目

DECISIONS                     ← 段落：决策
  D1: 只做 + - ×              ← 编号条目
     reject: 除法   due: 用户没要求   ← 行内标签

OPEN                          ← 段落：开放项
  ?1: 结果带 "=" 吗   default: 不带   ← 编号 + 行内标签

META                          ← 段落：元信息（系统管）
  commits: 7
```

## 7. 写档案时最常见的几个误区

1. **把没定的事写进 CONTRACT** → 应该写进 `OPEN`（并带 `default:`）。
2. **要"长相一样"却不贴 SNIPPET** → FIDELITY 写了 artifact 但没原文，AI 还是自由发挥。
3. **只记"要了什么"，不记"否决了什么"** → 复现的 AI 会把砍掉的捡回来。
4. **自己手写 META** → 不该碰，系统自动填。
5. **一句话能说清的，写成长篇** → DECISIONS/OPEN 每条只允许一句话结论，禁止"思考过程"。
6. **需求里没提的功能加进档案** → 明确禁止，AI 只实现用户点名的。
