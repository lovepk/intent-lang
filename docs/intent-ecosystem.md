# 应用场景与生态 (Scenarios & Ecosystem)

> 本文回答两个问题：**IL 这套东西能用在哪些场景**、**如何围绕它建立生态**。
> 属于愿景/方向性文档；语言本体的硬规则见 `intent-spec.md`，目标与非目标见 `intent-goals.md`。

---

## 1. 核心价值

一句话：**把"意图"变成独立于会话、可移植、可复现、可审计的资产。**

现有对话式 LLM 的四个结构性缺陷（详见 `intent-goals.md` §3）——意图易失、对话不可移植、输出不可复现、意图无档案——都源于"意图只活在会话里"。IL 把意图抽出来，变成一份可像代码一样 diff / commit / 回滚 / 交付的档案，由此展开全部场景。

---

## 2. 应用场景

### 2.1 跨会话 / 跨模型的持续开发
现在换模型或新开会话就得从头描述需求。用 IL：档案是唯一持久资产，任意 LLM 只凭【规范 + 档案】就能接着干，并能复现既有成果。适合长周期项目、模型迭代频繁的团队。

### 2.2 去厂商锁定 / 可移植交付
`il repro --key B` 已演示：同一份档案喂给不同模型，ACCEPT 行为验收均通过。交付物不再是一坨代码，而是**档案**——任何人可用任意模型重建。企业可据此避免被单一模型供应商锁定。

### 2.3 可复现构建（意图层的 Nix）
`repro + accept + SNIPPET` 构成"给定档案 → 得到行为/形态一致产物"的闭环：
- 默认行为一致（ACCEPT 逐条验收）；
- 点名形态一致（SNIPPET 原文逐字出现）。
适合对复现性有硬要求、又希望引入 LLM 的构建/交付流水线。

### 2.4 非程序员的规格交付
IL 人类可读优先（原则 4），产品、业务、客户能读懂甚至书写意图，LLM 负责实现与验收。降低"需求 → 实现"的翻译损耗与歧义。

### 2.5 审计 / 合规 / 知识沉淀
commit 链让每条需求可追溯来源、可 diff、可回滚（见 `intent-commands.md` 的 `log/show/rollback`）。适合受监管行业、团队交接（不必翻聊天记录）、教学与经验沉淀。

### 2.6 模板与共享规范复用
`<ref: 档案名#条目ID@版本>` 已能引用公共档案（见 `intent-spec.md` §2.6）。可沉淀"公司错误处理规范""UI 风格档案""基础库行为"等，各处**引用而非复制**，版本锁死、避免多处漂移。

---

## 3. 生态的分层（供定位，不是待办）

按 **语言 → 工具 → 资产 → 网络 → 治理** 五层看：

- **L1 语言与工具**：规范、parser/lint/diff、CLI、编辑器高亮。**当前主要在这一层。**
- **L2 Provider**：可替换的多模型接入。
- **L3 资产市场**：档案注册表、按名+版本拉取。
- **L4 平台与集成**：托管仓库、CI 复现门禁。
- **L5 治理与社区**：规范版本治理、benchmark、示例库。

**分层只用来定位，不意味着要逐层建设。** 下面只挑当下真正该做的。

---

## 4. 近期务实清单（先做这些）

原则：只做**现在就能验证、成本低、直接加固核心主张**的事。每项给出「为什么现在 / 做什么 / 验收 / 成本」。

> **按 §2 定位（协议而非产品）**，务实重点应从"给 CLI 加功能"转向"**让其他 agent 能直接消费**"：优先把 record / reproduce / verify / lint 包成 **agent 集成面**（如 MCP tool 或库），CLI 退居调试/演示。CLI 层的功能（如多 Provider）只是基础，真正"供其他 agent 使用"还需要一个 agent 可直接调用的接口。
>
> **进展**：内核已下沉到 `internal/agent`；`il mcp`（stdio）已提供纯工具面（`il_parse`/`il_lint`/`il_diff`/`il_resolve`/`il_read`/`il_commit`/`il_log` + prompts + resources），默认不调模型（BYOM）；配置 API key 时额外提供可选编排工具（`il_record`/`il_reproduce`/`il_accept`）；`pkg/intentlang` 已提供 Go 嵌入 API。

### 4.1 多 Provider：证明"可移植"不是口号（P0）
- **为什么现在**：项目最核心的主张是"档案可移植、不被单一模型锁定"，但目前只有 DeepSeek 一个实现。这是主张成立与否的关键证据，且成本很低。
- **做什么**：把 `internal/provider/deepseek.go` 里的 OpenAI 兼容协议抽成通用 provider，DeepSeek 退化为一个配置；支持第二个端点/模型（`--provider` 或环境变量）。
- **验收**：同一份档案，两个不同的 OpenAI 兼容端点各跑一次 `repro → accept`，均通过。
- **成本**：小。

### 4.2 `il fmt`：手写档案不再靠人肉排版（P0）
- **为什么现在**：档案格式有硬约束（段头顶格、2 空格缩进、段顺序、SNIPPET 缩进），现在只能靠人守；这是每天都会碰到的小摩擦。
- **做什么**：新增 `il fmt`，规范化排版且**幂等**；复用现有 `Parse`/`Canonical`。
- **验收**：对 `testdata/*.il` 连续两次 `fmt` 输出一致；`Parse→Canonical` 往返稳定。
- **成本**：小。

### 4.3 `il lint` 能当门禁（P0）
- **为什么现在**：`il lint` 已经能查结构矛盾，但只打印结果、退出码恒为 0，无法接 pre-commit / CI。
- **做什么**：加 `--fail-on error`（有 error 时非零退出）；README 给一个 pre-commit 示例。
- **验收**：含 error 的档案 `lint --fail-on error` 退出码非零。
- **成本**：极小。

### 4.4 规范版本纪律（P1）
- **为什么现在**：生态迟早要按版本引用规范；先有版本号和变更记录，成本几乎为零。
- **做什么**：规范写明语义化版本与兼容规则（minor 只增不改、major 才破坏）；建 `CHANGELOG`。
- **验收**：`CHANGELOG` 记录一次真实变更；旧档案在新 minor 下仍可解析。
- **成本**：极小。

### 4.5 明确暂缓（现在做是空转）
以下**不做**，等 4.1–4.4 落地、且有真实外部档案/用户后再谈：

- 档案注册表 / `<ref>` 远程依赖 / lockfile
- LSP、托管平台、公开 benchmark
- **理由**：它们都依赖"已有一批档案资产"这个前提。现在没有真实数据支撑，却会先背上维护成本。

## 5. 近期红线（做以上任何一项都不得违反）

1. **不干扰生成（原则 0）**：所有工具只能记录/校验，**不得**阻断、拒绝、重试或改写 LLM 的生成。
2. **复现自包含**：任何产物喂给 LLM 前，`<ref>` 必须已展开（`refs.Resolve`）；"失忆后仅凭 B 可复现"承诺不变。
3. **版本锁死**：引用与规范都必须显式带版本；不隐式跟随最新。
4. **人类可读优先（原则 4）**：新增工具的输出面向人时保留自然语言，不引入代码样语法。
5. **单元测试不依赖网络**：仅解析/校验/仓库层可离线测；真实 LLM 调用只出现在集成验证。

---

## 6. 一句话

**先把"多模型都能复现"和"档案好写、好查"这两件小事做实，比铺一整套平台更有价值。**
