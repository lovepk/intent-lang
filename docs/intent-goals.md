# 目标文档 (Goals)

## 1. 项目名称

**Intent Lang (intent-lang)** —— 一种给 LLM 使用的意图语言及其配套 agent 工作流。

## 2. 一句话愿景

让人与 LLM 的对话不再依赖"会话本身"，而是沉淀为一份**独立于会话、可移植、可复现的意图档案**；会话删除、人机失忆之后，仅凭【意图语言规范 + 意图档案】就能让任意 LLM 重建出**与原产物意图一致**的结果。

> "意图一致"是分层的：默认要求**行为一致**（同输入同输出，以 ACCEPT 验收为准）；只有档案显式点名锁定的部分（FIDELITY=artifact 时的 SNIPPET 等）才要求**形态一致**。详见 intent-spec §原则 3。

### 2.1 它是什么（定位）

IL 是 **agent 之间的意图交换格式 + 记录协议**，不是某个具体产品。

- **规范才是产品**：别人（其他 agent / 其他实现）消费的是**规范**；本仓库的 CLI 只是**参考实现与测试床**，不是被依赖的产品本体。
- **面向 agent**：主要使用者是 LLM agent，它们通过**接口**调用（MCP tool / 库 / 直接遵守双通道协议），而不是靠人点界面。
- **跨会话 / 跨模型 / 跨实现**：任何遵守规范的 agent，都应能读同一份档案、复现同一产物。
- **在技术栈中的位置**：处于**格式/协议层**，不处应用层。类比——Markdown（内容格式）、LSP（编辑器↔工具的协议）、Git（版本化+可交接）、npm（包格式+依赖）。

### 2.2 它不是什么

- **不是产品**：不做面向终端用户的独立应用、SaaS、平台（详见 §5 非目标）。
- **不是通用编程语言**：不追求图灵完备，不被"执行"，只被"消费"。
- **不是编译器**：不追求脱离 LLM 独立运行（仅列为远期探索）。
- **不是某个模型的私有格式**：与具体 provider 解耦（多 Provider 已支持）。
- **不是聊天记录的替代品**：它记录的是**消歧后的意图**，不是对话流水。

## 3. 要解决的问题

现状的四个结构性缺陷：

1. **意图易失**：人与 LLM 的每次交流都带着意图，但人类记不住曾经的意图（更关注未来的当下）；会话一旦删除，LLM 也不记得针对每个意图的输出。双方都没有可靠保存。
2. **对话不可移植**：换一个 LLM / 新开一个会话，就要从头重新描述需求，无法复用过去的成果。
3. **输出不可复现**：LLM 是概率模型，同一段描述喂给不同模型或不同时刻，产物会漂移，无法保证"同样的意图得到落实"。未经消歧的描述每次会被各自理解，导致行为与形态都不可控。
4. **意图无档案**：现有系统只管理"生成的最终代码/回答"，不管理"交流过程中意图的演化轨迹"，因此无法 diff、无法回滚、无法审计。

## 4. 目标 (Goals)

- **G1 定义意图语言 (IL)**：一门给 LLM 读写、**同时人类可读（非程序员也能看懂）**的意图语言。它既是 LLM 的交换格式，也是可被 LLM 作为规范执行的标准。语言本体见 `intent-spec.md` v2.0（五原则，原则 0 = 记录优先、不干扰生成 + 头四段/七段结构）。
- **G2 定义双通道对话协议**：agent 每轮请求 LLM 时，LLM 除正常回答用户外，还需额外产出/更新一份由意图语言编写的"意图程序档案"。档案的更新方式**像程序员修改代码一样**：增量、可 diff、可 commit、可回滚。
- **G3 实现可复现闭环**：经过 n 次交流得到产物 C 与档案 B 后，删除对话 session（人机双失忆）；再次把【意图语言规范 + 档案 B】交给 LLM-A 或任意 LLM-B，能重建出意图一致的 C'。分两层验收：
  1. **默认：行为一致**——C' 满足档案 ACCEPT 的全部用例（同输入同输出）。
  2. **点名：形态一致**——仅对档案用 SNIPPET 锁定的部分要求逐字/结构相符。
  不被点名的实现细节允许不同，不视为复现失败。
- **G4 档案可审计**：档案 B 带完整演化历史（版本、commit message、变更 diff、关联的用户消息），每一条需求可追溯到哪一次交流引入。
- **G5 提供验收工具**：① ACCEPT 行为验收（可运行产物逐条跑用例）；② 对被 SNIPPET 点名的部分做原文存在性检查。二者共同构成"可复现"的可测验收依据。
- **G6 真实模型闭环验证**：核心闭环在真实 LLM 上验证（本项目已接 DeepSeek；多模型通过 Provider 接口扩展）。

## 5. 非目标 (Non-Goals，第一阶段明确不做)

- 不追求意图语言**图灵完备**——它是"可执行规格/档案语言"，不是通用编程语言；需要图灵完备行为时，落地点仍是产物 C（由档案还原出的目标程序）。
- 不做图形界面、Web 服务、多人协作等外围设施。
- 不把本项目做成具体产品/平台（无 GUI、无 Web 服务、无账号）。若提供 agent 接口，仅限**本地**形式（如 MCP stdio、库）；不定义跨 agent 的网络协议 / 权限模型。
- 不试图让 LLM 自动生成"意图语言编译器"并能脱离 LLM 独立运行（列为远期探索）。
- 项目运行需真实 LLM API（通过 `.env` 提供 key）；单元测试不依赖网络（仅解析/校验/仓库层）。

## 6. 关键术语

| 术语 | 含义 |
|------|------|
| **IL (Intent Language)** | 意图语言：人类可读、LLM 可读写的档案描述语言。 |
| **意图档案 B** | 用 IL 编写的产物档案，随对话像代码一样被反复修改。 |
| **产物 C** | 交流最终得到的交付物（如一个计算器程序）。 |
| **对话 session** | 一段人机对话的历史上下文，易失。 |
| **规范注入** | 每次请求前把 IL 语法规范作为上下文喂给 LLM。 |
| **复现 (Reproduce)** | 给定【规范 + B】，让一个 LLM 重新生成 C'。 |
| **LLM-A / LLM-B** | 编译/写档的一端与复现的一端，可以是同一个模型的不同实例，也可以是不同模型。 |
| **Provider** | 可替换的 LLM 接入抽象（目前为 DeepSeek，可按接口扩展）。 |
| **FIDELITY** | 档案声明的复现保真层级：`behavior`/`structure`/`artifact`，决定语言需要锁到多重。 |
| **DECISIONS** | 决策日志段：记录"采纳了 X、否决了 Y"，防止复现端把否决的选项重新发明。 |
| **SNIPPET** | 黄金代码段：artifact/structure 层直接嵌入的实现原文，最强消歧锚点。 |
| **OPEN** | 开放项段：尚未消歧的点，必须带 default，复现端按默认处理、不自行发挥。 |
| **协议 / 参考实现** | 规范定义"怎么做"；本仓库 CLI/库是参考实现与测试床，不是被依赖的产品本体。 |
| **Agent 集成面** | 其他 agent 消费 IL 的接口：MCP tool / 库 / 直接遵守双通道协议。 |

## 7. 成功判据

- 端到端 demo（计算器场景）中：完成 n 次交流 → 删除 session → 用【规范 + B】复现 → ACCEPT 行为验收全过；被 SNIPPET 点名的部分原文逐字出现在产物中。
- 同一份 B 喂给两个不同的真实模型（key A / key B），ACCEPT 行为验收均通过（实现文本可不同，属预期）。
- 档案 B 的 commit 历史可完整回放：回滚到任一版本后重新复现，能得到对应历史意图的合理还原。
