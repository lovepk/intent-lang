# 多档案引用设计 (Design) — v0.1 草案

> 状态：设计草案，待评审。
> 目标：让意图档案能引用其它档案的条目，实现"单点维护 + 模块化"，**同时不破坏 IL 最核心的承诺——档案自包含、失忆后仅凭 B 可复现**。

---

## 1. 要解决的问题

现状：一个产物 = 一份 `.il`，完全独立。两个痛点：
1. **复制漂移**：两个产物共享同一意图（如"错误处理规范"），只能各自复制 → 改一处忘另一处。
2. **大档案不可维护**：复合系统（订单=支付+库存+通知）塞进一个文件会膨胀到 LLM 无法稳定全量重写。

目标：支持 `A.il` 引用 `common.il` 的某条 R，让共性单点维护、大意图可拆分。

## 2. 核心设计：两层档案

**引用不能破坏"自包含可复现"，解法是把档案拆成两层：**

| 层 | 谁写/维护 | 有无引用 | 用途 |
|---|---|---|---|
| **源档案 (source)** | 人 + LLM 对话维护 | 可含 `<ref>` | 唯一的编辑对象 |
| **展开档案 (expanded)** | 机器生成 | 无引用，全物化 | 喂给 LLM 复现/复现验收的对象 |

```
源档案 order.il（编辑态）
  CONTRACT
    R1: 支付见 <ref: payment.il#R2@1.3>
    R2: 库存扣减见 <ref: stock.il#R4@2.0>

        │  resolve + materialize（机器）
        ▼
展开档案 order.expanded.il（自包含，喂 LLM 用）
  CONTRACT
    R1: <payment.il@1.3 的 R2 原文已拷入，来源: payment.il#R2@1.3>
    R2: <stock.il@2.0 的 R4 原文已拷入，来源: stock.il#R4@2.0>
```

**关键保证**：LLM（写档和复现两端）永远只见展开后的自包含文本 → "失忆后仅凭这份档案可复现"原样成立。引用是**源层的编辑便利**，不是运行时语义。

## 3. 引用语法

引用放在条目文本内，格式（机器可解析、人类可读、和普通文字可区分）：

```
<ref: <档案名>#<条目ID>@<档案版本>>
```

- `<档案名>`：被引用档案的文件名（不带 `.il`）
- `<条目ID>`：目标档案里的 R/A/D/? 编号
- `<档案版本>`：目标档案 `INTENT name@ver` 的版本（如 `1.3`）

示例：
```
R1: 错误处理遵循 <ref: common#R3@1.2>
R5: 展示格式见 <ref: style#A1@0.9>
```

规则：
- 引用**必须带版本**——不允许"引用最新的"，否则源档案被被引档案更新默默改变（打破"已消歧事实稳定"）。
- 引用粒度到**条目**（最细）；需要整个档案时 = 引它的多条，或将来加"整档案引用"。
- 引用可以出现在源档案的任意段条目里。

### 3.5 对 IL 语言规范（il-spec v2）的具体改动

引用要成为语言的一等语法元素，需动这几处规范：

**a) il-spec 新增"引用"章节**（定位在 §2 骨架/§3 段定义附近）：
- 定义 `<ref: name#id@ver>` 为**合法的条目内容标记**，与 `->`、`reject:` 等并列的语法元素。
- 明确"哪些段允许引用"：仅 `CONTRACT` / `ACCEPT` / `ANCHORS`（行为事实、验收、示例可共享）。`DECISIONS`/`OPEN`/`META` 禁止引用（决策与待定项是档案私有的）。
- 版本必填；`@ver` 与目标 `INTENT name@ver` 一致。

**b) SpecPrompt 增加**：
- 让写档 LLM 知道"可以写 `<ref>`，且知道何时该用引用（本档案某事实属于另一个档案时，优先引用而非复制）"。
- 警告："<ref> 不是把整行占掉，你可以在它前后继续写本地约束"（对应 Q3）。

**c) 解析器（Parse）**：语法层认出 `<ref>` 标记不报错（当前 parser 会把整行当普通文本，ref 作为行内容的一部分合法即可；真正的语法校验在 resolve 阶段）。

**d) lint 增规则**：
- 引用格式非法（缺版本 / 格式错）→ error。
- 引用出现在禁止的段（DECISIONS/OPEN/META）→ error。
- 悬空引用（目标档案/版本/条目不存在）→ 由 resolve 报，lint 只做源层语法预检。

**e) 语法高亮（VS Code grammar）**：`.il` 中 `<ref: ...>` 标记为特殊 scope（如 `markup.other.reference.il`），一眼可辨。

**f) 编辑规则澄清**：改被引档案 = 被引方单独建档；引用方要跟进必须显式改 `<ref>` 版本（不自动跟随）。这保持了"已消歧事实稳定"。


## 4. 解析流程（机器做的三件事）

给定一份源档案，产出展开档案：

### 4.1 resolve（解析）
扫描所有 `<ref: name#id@ver>`，得到依赖清单：
```
order.il 依赖：payment.il@1.3, stock.il@2.0
```
- 在档案库（repo 或指定目录）里定位这些档案版本。
- 找不到文件 / 版本不存在 → resolve error，中止。

### 4.2 materialize（物化）
深度优先展开，把被引条目的原文拷入引用处，**保留出处标记**：
```
R1: 支付见 <ref: payment.il#R2@1.3>
→ R1: 处理支付时校验签名（原文来自 payment.il R2，版本 1.3）
```
- 被引档案自己也有 `<ref>` → 递归展开（依赖链）。
- **保留来源**：物化后的行尾附 `来源:` 注释，人类/审计可追溯。
- 循环引用 → 检测到即中止报错（A 引 B，B 引 A）。

### 4.3 validate（校验）
展开后的自包含档案再过一遍标准 `il.Validate()`，确保物化没破坏结构。

## 5. 对现有流程的影响

| 环节 | 改动 |
|---|---|
| **对话建档 (chat)** | LLM 写的是**源档案**，可写 `<ref>`；SpecPrompt 增加引用语法说明。存库的是源档案。 |
| **分层一致性 (L1/L2)** | 在源层工作：L1 机器 diff 比较源 before/after；L2 记录员整理的是源档案。 |
| **复现 (repro)** | 喂给 LLM 前先 materialize 成展开档案。 |
| **accept/compare** | 同样先用展开档案。 |
| **lint** | 源档案 lint 时跳过 `<ref>` 内容（引用处待物化），但**校验引用语法**（格式对、版本带、目标存在性由 resolve 查）。 |
| **archive 仓库** | 一个仓库可存多档案；引用跨档案时需能定位被引档案（同 repo 或显式路径）。 |

## 6. 版本与库的组织

最小方案（第一阶段）：
- **单仓库内引用**：`.il/` 目录下可存多份档案（`payment.il`、`stock.il`、`order.il` 各自独立 commit 链）。引用解析在仓库内按名字+版本找。
- 版本来自各档案 `INTENT name@ver` 的自报版本（Agent 维护，建档时递增）。

跨仓库/外部依赖 → 第二阶段（类似 go mod 的 registry），不在本次。

## 7. 边界与错误处理

| 情况 | 处理 |
|---|---|
| 引用了不存在的档案 | resolve error，提示"payment.il 不存在于本仓库" |
| 版本不存在 | resolve error，提示可用版本 |
| 循环引用 (A↔B) | materialize 时环检测，中止报错 |
| 被引条目已删（悬空） | resolve error；源档案 lint 提示 |
| 被引档案自身有引用 | 递归物化（深度有限，如 ≤16 防深链） |
| 展开后校验失败 | 报 materialize 内部错误（一般不会，因物化只拷文本） |

## 8. 不做的事（第一阶段）

- ❌ 跨仓库/registry 依赖（外部拉取）
- ❌ 整档案引用糖（`<ref: common@1>` 全引）——先条目级
- ❌ 依赖版本自动升级（引用锁死版本，升级 = 显式改 `<ref>` 再建档）
- ❌ 引用进 DECISIONS/OPEN/META（只允许 CONTRACT/ACCEPT/ANCHORS 条目引用——这些是"事实/用例"，可共享；决策/开放项是档案私有的）

## 9. 待评审问题

- **Q1**：引用是否能用于 CONTRACT 之外？草案限 CONTRACT/ACCEPT/ANCHORS（共享"行为事实/验收"合理），DECISIONS/OPEN 保持私有。认可吗？
- **Q2**：物化后保留 `来源:` 标记——会影响复现端吗？建议保留（透明可审计），LLM 该无视来源注释。认可吗？
- **Q3**：源档案里 `<ref>` 处若同时写了自己的本地补充文字（如 `按 <ref> 且本地再校验余额`）——允许"引用+本地约束"并存吗？草案允许（引用不是整行替换，只是嵌入一段原文）。
